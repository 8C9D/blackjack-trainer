# CLAUDE.md

## What this is

A blackjack practice trainer shipped as two artifacts from one repository: a frontend-only Angular web app and a native SwiftUI iPhone app under `ios/`.
It drills four skills against published Blackjack Apprenticeship charts: basic strategy, running count, true count, and Hi-Lo deviations.
There is no backend, no network call in app code, and no account.
The only persistence is `localStorage` on the web and `UserDefaults` plus iCloud key-value store on iOS.

`README.md` is the long-form description of every feature; this file is the working orientation.

## Stack

- Angular 22 standalone components, signals, `provideRouter`, zoneless (no `polyfills` entry in `angular.json`, so zone.js is absent).
- TypeScript 6.0, `strict` plus `noImplicitOverride`, `noPropertyAccessFromIndexSignature`, `noImplicitReturns`, `noFallthroughCasesInSwitch`, and `strictTemplates`.
- SCSS, no UI framework.
- Vitest 4 with jsdom, run through the `@angular/build:unit-test` builder, configured by `vitest.config.ts`.
- Playwright for a Chromium-only E2E suite in `e2e/`.
- Node 22 (`.nvmrc`), npm 11.12.1 (`packageManager` in `package.json`).
- No ESLint in the tree; `tsc` plus Prettier plus `tools/check-records.mjs` are the whole lint gate.
- iOS: SwiftUI, Swift 5 language mode, deployment target iOS 17, iPhone-only, `.xcodeproj` generated by XcodeGen from `ios/project.yml` and committed.

## Commands

```bash
npm start                    # dev server at http://127.0.0.1:4200/
npm test                     # unit tests (CI=true for a single run)
npm run test:coverage        # tests + v8 coverage against the thresholds in vitest.config.ts
npm run typecheck            # tsc --noEmit over the app, spec and e2e projects
npm run lint                 # typecheck + prettier --check + the records gate
npm run build                # production bundle in dist/blackjack-trainer/
npm run e2e                  # Playwright against ng serve
E2E_SERVER=dist npm run e2e  # Playwright against the production bundle, which it builds itself
npm run export:fixtures      # regenerate ios/Fixtures/*.json from the TypeScript engines
```

`npm run e2e:install` installs the Chromium build once before the first E2E run.

iOS is built and tested with `xcodebuild -scheme BlackjackTrainer -destination 'platform=iOS Simulator,name=iPhone 16 Pro' build test` from `ios/`, with `swiftformat --lint .` and `swiftlint lint` as its lint gate.
Regenerate the project with `cd ios && xcodegen generate` after changing `ios/project.yml` or adding files.

## Traps worth knowing before you run anything

- **Do not run `npx vitest run` directly.** The specs rely on globals the Angular unit-test builder injects, so a bare vitest invocation fails every file with `describe is not defined`. Always go through `npm test` / `ng test`.
- **`npm run lint` includes `tools/check-records.mjs`**, a project-specific gate over `PROD-READINESS.md`, `LAUNCH-CHECKLIST.md` and `reviews/*.md`. It checks anchors, pins every `file:line` citation to a content fragment, refuses transcripts that could not have been printed by the command shown, and refuses volatile figures (test counts, coverage percentages) in prose outside a `gate-table` marked table. Its escape hatches are HTML-comment markers documented in the header of the tool. Editing those documents without reading that header will make lint red.
- **The records gate walks git history**, so a shallow clone makes it fail. Both CI jobs that run lint set `fetch-depth: 0`.
- **CI fails on parity-fixture drift.** Any change to the TypeScript engines must be followed by `npm run export:fixtures`, and the resulting `ios/Fixtures/*.json` committed. Fixtures for features archived out of the iOS build stay committed and unconsumed on purpose.
- **The `dist` E2E lane builds what it serves** and refuses to reuse a server it did not start, because a stale `dist/` once let the suite report green against a bundle from another commit. Use `E2E_PORT=4300` to run a second suite alongside the first.
- Prettier ignores `ios/`, `public/cards/`, `.agents/`, `.codex/`, and `package-lock.json`; see `.prettierignore` before reformatting anything.

## Architecture landmarks

- `src/app/core/services/` holds the pure engines, which have no Angular runtime dependency beyond the `@Injectable` decorator and are instantiated directly in tests: `basic-strategy-engine`, `counting-engine`, `deviation-engine`, `deviation-evaluator`.
- `src/app/data/` holds the H17/S17 basic-strategy and deviation charts and the 58 counting systems as static TypeScript literals. The `SUR_*` chart cells are an internal extension that encodes the published surrender footnotes inline.
- True count truncates toward zero (`Math.trunc`), which is this trainer's stated convention and is asserted across both platforms.
- `RANDOM_SOURCE` in `core/services/random-source.ts` is the RNG seam. Appending `?seed=<integer>` to any URL pins every draw so a session replays exactly; the E2E suite depends on it.
- `core/services/storage.ts` is the single tolerant `localStorage` reader/writer. A malformed payload degrades to defaults field by field, and a refused write raises a sticky, non-dismissible app-wide notice, because a silently dropped write means an evening of practice lost with nobody told.
- The backup file is defined by declared keys rather than a key-prefix sweep, because the web app ships on the shared `8c9d.github.io` origin where a prefix sweep would read and wipe a neighbouring project's storage.
- `ios/` mirrors the web engines in Swift; parity is enforced by replaying the exported fixture vectors in `ios/BlackjackTrainerTests/*ParityTests.swift`.
- `archived/` holds the nine features cut from the iOS v1.0 build, with per-feature restore instructions in `archived/RESTORE.md`. The authoritative full-featured tree is the tag `pre-trim-full-featureset` (also the branch `archive/full-featureset`). The web app still ships all nine, so it is the living behavioural reference.

## Conventions

- Commit subjects are lowercase sentences describing the behaviour change, not conventional-commit prefixes; the early history used prefixes and the recent history does not.
- Markdown in this repo is one sentence per line.
- Point-in-time reports get a dated closing note rather than being edited to match a later tree, because a review's evidence was true when written.
- When a web behaviour changes, the iOS mirror change is a separate commit, usually titled `feat(ios): mirror ...` or `fix(ios): mirror ...`.
